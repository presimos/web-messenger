# Проверка оформления кода

## Применённые соглашения

- Backend разделён на модули по ответственности: маршруты авторизации, маршруты чатов, схемы данных, ORM-модели, подключение БД и безопасность.
- Имена Python-функций, переменных и полей моделей записаны в `snake_case`; имена классов — в `PascalCase`.
- В публичных обработчиках backend указаны аннотации типов; Pydantic-схемы ограничивают длину строк и проверяют пустые значения.
- Ответы API формируются отдельными схемами; поле `password_hash` не включено в ответ пользователя.
- В React-компоненте используются типы TypeScript для пользователя, чата и сообщения; API-функция обобщена типом результата.
- Секрет и строка подключения задаются через переменные окружения, файл `.env` включён в `.gitignore`.
- Из подтверждённых проверок стиля в проекте есть Oxlint для frontend (`pnpm lint`). Он завершился успешно. Отдельный форматтер Python и инспектор на соответствие конкретному ГОСТ в проект не подключены.

## Инспектирование вручную

Проверены границы модулей и фактические контракты: маршруты используют Pydantic-схемы, обращаются к данным через SQLAlchemy, а проверка JWT и паролей вынесена в `security.py`. Условия доступа к чату проверяются до чтения истории и при WebSocket-подключении. Для тестируемого поведения добавлены сценарии позитивных и отрицательных ответов.

## Ограничения текущей версии

Это учебный MVP. `ConnectionManager` хранит соединения в памяти одного процесса; отдельной распределённой рассылки нет. PostgreSQL-зависимость и конфигурация подготовлены, но подтверждены только SQLite-тесты. Автоматическая проверка форматирования и ГОСТ для Python не заявляется; в проекте нет собственного корпоративного регламента кодирования.
