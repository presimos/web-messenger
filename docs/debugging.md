# Отладка проекта

## Средства

- PowerShell — запуск backend, клиентских команд и проверок.
- Uvicorn — локальный запуск FastAPI и просмотр журнала HTTP-запросов.
- FastAPI `/docs` — просмотр контрактов и ручная отправка HTTP-запросов.
- Pytest с FastAPI TestClient/HTTPX — воспроизведение HTTP- и WebSocket-сценариев.
- Сообщения статусов и ошибок в интерфейсе помогают увидеть отказ API или потерю WebSocket-соединения.
- `pnpm build` запускает проверку TypeScript и сборку Vite; `pnpm lint` запускает Oxlint.

## Алгоритм локальной проверки

1. Запустить backend из папки `backend` командой `uvicorn app.main:app --reload`.
2. Открыть `/health`; ожидать HTTP 200 и JSON `{"status":"healthy"}`.
3. Зарегистрировать тестового пользователя, войти и получить JWT.
4. С Bearer JWT запросить профиль и список чатов, затем создать тестовый чат.
5. Подключиться к WebSocket участником чата и отправить JSON с непустым `body`.
6. Проверить получение сообщения участниками и наличие сообщения в HTTP-истории.
7. Повторить проверки отрицательных условий: неверный пароль, отсутствие JWT, пользователь не участник чата, некорректное тело сообщения.
8. Запустить Pytest; после изменений клиента выполнить `pnpm build` и `pnpm lint`.

## Зафиксированные результаты

Последний выполненный для отчёта запуск: 9 тестов Pytest пройдены; проверены health endpoint, регистрация, вход, JWT-профиль, дублирование имени, отказ при неверном пароле, CORS, модели БД, создание чата, права членства, WebSocket-рассылка и история сообщений. `pnpm build` и `pnpm lint` завершились успешно.

В ранее записанном журнале ручного запуска были ответы HTTP 200 на health, вход и профиль, HTTP 201 на регистрацию и принятое WebSocket-соединение. В этом запуске базы использовалась SQLite. Подключение к PostgreSQL отдельно не проверялось.

## Обработка ошибок

- Повторное имя пользователя возвращает HTTP 409; обработчик откатывает незавершённую транзакцию.
- Неверный пароль и отсутствующий или недействительный JWT возвращают HTTP 401.
- Чат или HTTP-доступ к нему при отсутствии членства возвращает HTTP 404.
- WebSocket с недействительным JWT закрывается кодом 4401; пользователь без членства — кодом 4403.
- Ошибка формата сообщения в WebSocket возвращает JSON с полем `error`, соединение остаётся открытым.
- Для локального запуска используется SQLite. Для PostgreSQL нужно задать `DATABASE_URL` и проверить подключение с доступными учётными данными.
