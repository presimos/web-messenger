# Интеграция модулей

## Контракты обмена

| Интерфейс | Запрос/событие | Ответ/результат |
|---|---|---|
| `POST /auth/register` | JSON: `username`, `password` | Профиль пользователя, HTTP 201; пароль не возвращается |
| `POST /auth/login` | JSON: `username`, `password` | `access_token`, тип `bearer` |
| `GET /auth/me` | `Authorization: Bearer <JWT>` | Профиль текущего пользователя |
| `POST /chats` | JWT и JSON с `title`, `member_usernames` | Созданный чат, HTTP 201 |
| `GET /chats` | JWT | Список чатов участника |
| `GET /chats/{id}/messages` | JWT, `limit` от 1 до 100 | История чата, доступна участнику |
| `WS /ws/chats/{id}?token=<JWT>` | JSON-сообщение `{"body":"..."}` | Сохранённое сообщение рассылается подключённым участникам |

## Подключённые библиотеки и назначение

- FastAPI предоставляет HTTP-маршруты, зависимости и WebSocket endpoint.
- Pydantic проверяет входные модели `UserCreate`, `ChatCreate`, `MessageCreate` и формирует схемы ответов.
- SQLAlchemy связывает обработчики с ORM-моделями и выбранной SQL-базой через `DATABASE_URL`.
- `python-jose` подписывает и проверяет JWT; `pwdlib` с Argon2 хеширует пароли.
- React выполняет запросы через браузерный `fetch` и открывает стандартный браузерный `WebSocket`.
- Vite собирает и обслуживает клиент; CORS в FastAPI разрешает локальные адреса Vite `localhost:5173` и `127.0.0.1:5173`.
- HTTPX и Starlette TestClient используются Pytest для HTTP- и WebSocket-проверок.

## Порядок интеграции

Графический алгоритм обмена сообщением: [message-flow.png](message-flow.png).

1. Клиент получает JWT через `/auth/login` и хранит его в `localStorage`.
2. Для HTTP-запросов клиент передаёт JWT в заголовке `Authorization`.
3. FastAPI проверяет токен зависимостью `get_current_user`, затем обработчик работает с пользователем из БД.
4. При выборе чата клиент загружает историю по HTTP и открывает WebSocket с тем же JWT.
5. WebSocket-обработчик проверяет JWT и наличие участника в `chat_members`.
6. После получения JSON сервер проверяет схему сообщения, записывает строку в `messages` и рассылает её активным подключениям данного чата.

## Проверяемые границы интеграции

Тесты проверяют полный сценарий регистрации, входа и чтения профиля; передачу JWT к защищённому маршруту; создание чата; отклонение пользователя без членства; подключение участников по WebSocket; сохранение и получение сообщения в истории. База тестов создаётся отдельно в SQLite-файле временной папки. PostgreSQL в текущем наборе проверок не используется.
